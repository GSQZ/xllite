# 掌上新理工 · HarmonyOS 版实现（API 23+）

本 PR 向 `harmonyos` 分支提交掌上新理工的 HarmonyOS 原生实现。仓库只包含鸿蒙主工程本体（173 个文件），不含与本工程无关的附属项目或构建产物。

## 这是什么

面向新疆理工学院的校园应用，使用 ArkTS / ArkUI 重写，最低支持 API 23（HarmonyOS 6.1），目标与编译环境为 API 26。视觉方向为鸿蒙原生沉浸玻璃。

与 `main` 分支的 Flutter 实现共用同一套学校接口与网关契约，但平台与代码完全独立。

## 相对 Flutter 版做了哪些鸿蒙适配

Flutter 版无法实现、只有落到系统层才拿得到的能力：

- **实况窗**：课前倒计时与待办计时以 `TIMER` 场景进入胶囊、锁屏与通知中心，按错误码给出处置提示。
- **小艺意图**：已核实平台契约——SDK 侧 101 个标准意图 schema 中不含创建待办或提醒的意图，`JumpFunctionPage` 只能打开页面不能填充内容，故可落地目标只能是打开课表页。**当前代码尚未接入**，边界与实施条件见 `docs/XIAOYI-INTENT-INTEGRATION.md`。
- **原生沉浸材质**：API 26 设备走 `ImmersiveMaterial` 原生材质，低版本回落 ArkUI `backgroundEffect`。
- **系统提醒代理**：课程提醒交由 `reminderAgentManager` 托管，退出登录按 `groupId` 注销，不依赖落盘 ID。
- **桌面服务卡片**：`CampusFormAbility` 提供课表与待办卡片，快照失败时不注册提醒。
- **跨版本兼容**：最低 API 23，高版本能力一律经运行时版本判断后动态导入，不进入低版本调用路径。

## 已实现的业务

- 统一身份认证登录与会话缓存，卡片、余额、流水、电量、充值、课表、成绩、考试、培训、二维码、待办、个人信息。
- 课表支持周次视图、今日筛选、节次时刻解析，课程配色按标题哈希稳定分配。
- 待办支持增删改查、计时型实况窗、系统提醒、桌面卡片同步，退出登录按账号隔离清理。
- 电量查询支持宿舍绑定与充值下单；支付只做到跳转，应用侧无法观测支付结果，提交后如实提示"支付请求已提交，请到一卡通账户核对到账结果"，判定权交回用户。
- 主题跟随系统深浅色，配色通过 WCAG 4.5:1 对比度校验。

## 目录结构

| 路径 | 职责 |
| --- | --- |
| `entry/src/main/ets/pages` | 页面 |
| `entry/src/main/ets/components` | 组件（含沉浸材质、玻璃底栏、课表网格） |
| `entry/src/main/ets/services` | 会话、网关、实况窗、提醒、待办、桌面卡片 |

| `tools` | 构建脚本与 10 套回归测试（Node mock 层） |
| `docs` | 契约文档与专题验收记录 |

## 验证方式

```powershell
npm test
```

覆盖 API23 兼容、品牌资源、课表与桌面卡片、网关契约、登录、材质加载、页面行为、服务层、UI 结构、配色对比度共 10 套用例。

签名材料、密钥、环境变量与本地 SDK 路径均不入库；`build-profile.json5` 的 `signingConfigs` 保持为空，签名需各自生成。

## 已知边界

- 当前处于开发与联调阶段，非正式发布版本。原生个人信息、余额、流水已有实现，其余业务待真实账号与原生协议验收。
- API 23 设备上实况窗无法控制自动结束与最长存活时间（相关参数自 API 24 / 26 起提供）。
- 支付链路仅做跳转适配，不在 App 内闭环微信 JSAPI 支付（服务端未提供签名契约）。
- 小艺意图当前只有契约结论，代码未接入；可落地目标也只能是打开课表页，创建待办在标准意图清单里没有对应项。
