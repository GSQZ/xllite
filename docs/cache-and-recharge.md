# 本地数据与充值

## 页面加载

课表、成绩、考试、个人资料、毕业情况、校园卡余额、宿舍电量和交易记录第一页保存本地快照。页面首次进入先显示快照，同时请求学校最新数据；刷新失败保留数据及原始更新时间，不把旧余额标成新余额。

- 数据由 `CampusStore` 使用现有安全存储保存，按 API 地址和已登录账号隔离，最多 32 个查询快照，总 JSON 长度限制 200 万字符。结构带版本前缀，损坏或超期时忽略，存储失败不阻断查询。
- 学业快照有效期 30 天，余额、电量、交易记录为 1 天。应用内重复进入，学业资源 5 分钟内复用，余额与电量 30 秒内复用；下拉刷新直接请求服务端。回到前台检查资源是否过期。
- 同时发出的相同查询合并请求；首页当前课表可直接提供给课表页，历史学期仍单独加载。
- 交易记录只保存第一页。缓存未成功更新前不续接分页，避免新旧流水混排。
- 缓存自动运行，界面不提供手动清理入口，也不显示「本地记录」等提示；仅在刷新失败时显示原始更新时间。`CampusController.clearCache()` 仍保留，供后续需要时调用。
- 退出或切换账号立即清除页面内存状态，旧请求不能重新填回页面。持久化数据仅供相应账号再次登录后读取。

## 宿舍

首次查询成功后保存当前账号的宿舍号，下次进入自动恢复并查询电量。失败的宿舍查询不覆盖已保存设置。「首页 → 宿舍电量 → 更换宿舍」可修改。旧版只有内存中的宿舍号无法跨进程迁移，需要在此版本首次设置一次。

## 充值

- 校园卡页面新增充值入口；宿舍电费页面包含查询、切换宿舍及充值。
- 金额选项、支付方式、是否支持他人充值、是否必须选择固定金额及电费支付密码要求均来自学校配置。电费 customfield 随配置传回。
- 提交前显示金额、充值对象和支付方式供用户确认。支付密码只在内存中使用，提交或进入后台即清空输入框。
- 支付宝 HTML 表单在 WebView 中提交；微信优先使用学校官方中转地址，微信 H5 跳转补齐学校 Referer；仅微信/支付宝协议交给外部应用。打开学校收银台或返回 App 不等于已支付。
- 当前学校账号配置提供支付宝、微信 WAP；纯微信 JSAPI 且没有可用中转链接时，显示学校微信渠道提示，保留核对入口，不自动重下单。
- 只有后端明确返回电费 `balance_payment` 才显示充值成功。其他订单保持待核对，返回后刷新余额、电量及流水；不以余额波动冒充订单确认。
- 请求期间禁止重复提交。结果未知或待支付时保留按账号隔离的最小操作标记（操作、金额、宿舍或对方学号，不含密码、支付链接或表单），重启后仍要求先核对再开始新充值。学校没有订单查询接口，故外部支付无法自动得出最终到账状态。

## 验证

回归覆盖缓存恢复、隔离、过期、损坏、容量、并发查询、旧请求失效、宿舍记忆、充值防重、重启后未知结果保护、小屏键盘与大字体。真实账号只读取充值配置，自动测试使用模拟支付响应，没有执行真实扣款。

课表日视图使用固定高度内容区，课程较多时内部滚动；空课日、忙碌日和切换动画保持相同高度。周视图仍按完整节次绘制，空周不收缩。
